MANUAL TEST DATA QUERIES
==========================================

After completing Scenario 1 order, run:

-- View created order
SELECT * FROM tblOrders WHERE buyer_id = (SELECT id FROM tblUser WHERE email = 'john@example.com');

-- View order items
SELECT oi.*, p.title FROM order_items oi 
JOIN tblProducts p ON oi.product_id = p.id
WHERE oi.order_id = 1;

-- View seller's received orders
SELECT o.* FROM tblOrders o
JOIN order_items oi ON o.id = oi.order_id
JOIN tblProducts p ON oi.product_id = p.id
WHERE p.seller_id = (SELECT id FROM tblUser WHERE email = 'sarah@example.com');

-- Calculate total revenue
SELECT SUM(total) as revenue FROM tblOrders;

-- Orders by status
SELECT status, COUNT(*) as count FROM tblOrders GROUP BY status;

PERFORMANCE METRICS TO TEST
==========================================

1. Order Creation Time: Should complete in < 1 second
2. Status Update: Should reflect immediately
3. Buyer Order List Load: < 500ms with 20+ orders
4. Admin Dashboard: Should load with order counts < 1 second
5. Search by Buyer: < 500ms
6. Search by Date Range: < 1 second


EDGE CASES TO TEST IN ORDERS
==========================================

1. Out of Stock Item
   - Expected: Cannot add to cart / shows error

2. Seller Deletes Item After Added to Cart
   - Expected: Item removed from cart or error on checkout

3. Multiple Orders Same Seller
   - Expected: Can be combined or separate (design choice)

4. Order Timeout on Checkout
   - Expected: Session preserved, can resume

5. Payment Failure (Simulated)
   - Expected: Order not created, money not taken

6. Concurrent Orders Same User
   - Expected: Both orders created successfully

7. Very Large Order Value (R10,000+)
   - Expected: Processes normally

8. International Address (not typically in ZA)
   - Expected: Accepted (or validation added)

9. Status Downgrade (Delivered back to Pending)
   - Expected: Admin can do this (or prevent if desired)

10. Delete User with Pending Orders
    - Expected: Cascade handled by FK constraint
